# 引文与删行契约（json 行集版）—— keeper v2

> 这是 exp02 `cite-and-compress` 技能在 OpenClaw 里的**重写版**。契约变了：不再输出
> `key_findings_used`（含 priority/context/摘要围栏），只输出**完全无用的行号**；
> 语料载体从"带行号的纯文本围栏"换成 **JSON 行集**（行号 = JSON 里的 `n` 字段）。

## 1. 你看到的取数结果长什么样

keeper 里每个取数工具的返回都是一个 **JSON 文本块**，行号 `n` 是全文唯一连续编号（从 0 开始，跨小节不重复）：

> 每一行的边界都是**完整的句子或表格行**（本地已按句号/分号/换行等边界切好，**不会出现半句话**，你不需要自己再拆行）。
> 读的时候把每一行当作一个**完整的信息单元**：行号 `n` 就是"原文里第 N 个完整单元"的编号；引用和删行都以**整行为单位**。

```json
{
  "tool": "hithink-finance-query",
  "query": "比亚迪 2023 2024 2025 营业收入 净利润 毛利率 ROE",
  "fetched_at": "2026-08-26 10:00:00+08:00",
  "sections": [
    {
      "id": "s0",
      "source": { "name": "同花顺 i问财 - 财务指标", "url": "", "check": "核对营收/净利口径与年份" },
      "rows": [
        { "n": 0,  "k": "h", "t": "比亚迪(002594) 财务指标" },
        { "n": 1,  "k": "v", "t": "营业收入: 2023=3929.6亿 2024=4681.6亿 2025=…" },
        { "n": 2,  "k": "v", "t": "净利润: 2023=55.1亿 2024=…" },
        { "n": 3,  "k": "u", "t": "（本行无信息含量，纯噪声示例）" }
      ]
    }
  ],
  "_meta": { "n_rows": 4, "hint": "按 n 引用；下次查询时用 discard_lines 报告完全无用的行号" }
}
```

字段：

- `n`：**行号**。你引用内容、报告删行都用它。全文唯一、稳定（插件压缩只删行、不改号）。
- `t`：该行的正文。
- `k`：行类型。`h`=标题/表头、`v`=数值/数据行、`t`=说明文本、`u`=噪声/无信息含量。
- `source.check`：告诉你要"核实/回到哪里去看"的提示（哪篇文章/哪个来源）。

## 2. 何时按本契约行事

**每次你在取数之后、要发起下一次 tool 调用之前**（包括准备最终报告前的最后一次查询）。

## 3. 怎么报告"完全无用的行"

- 在**下一个工具调用的参数**里加一个字段：

  ```json
  { "query": "…", "discard_lines": [3, 17, 22] }
  ```

- `discard_lines` **只用于最新拿到的那一份**（对话里最近一次工具结果、还没有 `_pruned` 标记的那份）。已经带 `_pruned`（已筛）标记的旧文档**不要再管**，更不要对它们输出行号。
- `discard_lines` 只放**完全没用**的行号（`n`）。判断标准极严：

  > **只要这一行里有一个字可能有用（哪怕只是作背景、佐证、上下文），就坚决不删。**
  > 宁可多留，不可误删。数据值、任何数字、任何可能与主题相关的描述，一律保留。

- 没有可删的行 → **省略** `discard_lines` 字段（不要写空数组也行，省略最干净）。
- `discard_lines` 是给 keeper 插件用的辅助字段，**取数工具会自动忽略它**，不影响你的查询——你只管诚实标注。

通常可删的：与本次主题无关的整块广告行、纯装饰分隔行、重复的表格边框、对自己判断无任何价值的模板噪音。
不可删的：任何数据行、任何可能被后续报告的章节引用的背景描述。

## 4. 铁律（最高优先级）

1. **只删"完全无用"，绝不含糊**。不确定 → 不删。
2. **行号只引用你"上一次"看到的那份结果的 `n`**，不要搞混批次（每次取数行号都从 0 重新开始）。
3. 不要自己编围栏、不要输出 priority/context/摘要（那是旧版契约）。
4. 本次没看到行号结构（例如工具报错、返回不是 JSON 行集）→ 不要输出 `discard_lines`。

## 5. 与 exp02 cite-and-compress 的差异（为什么这么改）

| 项 | exp02（旧） | keeper v2（本文件） |
|---|---|---|
| 方向 | 报"有用的行"（保留集） | 只报"完全无用的行"（删除集） |
| 字段 | key_findings_used（content/priority/context） | `discard_lines: [n,…]`（可有可无） |
| 载体 | `<<<CITATION_BLOCK>>>` + `N~ 行` 文本围栏 | JSON 行集，行号=`n` 字段 |
| 心智 | 亮点要评 priority | 只找噪声；有一个字有用就不删 |
| 风险 | 可能误删有用信息 | 天然保守，误删概率大幅下降 |
