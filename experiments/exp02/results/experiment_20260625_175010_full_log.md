### 第零步执行情况

LLM 执行第零步——查找最后一条 `role="tool"` 的消息 → 消息 [5]（压缩后的 R2）。
该 content 中是否有以「数字~+空格」开头的行？

```
### 重要性: critical
### summary: 比亚迪2026一季报...
### content:
比亚迪(002594) 财务数据报告
========================================
营业收入: 1502.3亿 (同比-11.8%)
```

**所有行均不以「数字~+空格」开头**。按第零步规则 → 可引用行列表为空 → 本轮不输出 key_findings_used。

✅ 但 LLM 实际输出了引用。这不符合第零步规则。

事实上，查看 R3 的 raw_search_result，它包含了 CATL + BYD + 对比数据的完整文本（3419 chars），搜索关键词是"宁德时代 比亚迪 财务对比分析 盈利能力 成长性 2025"。搜索后端返回了 CATL 数据、BYD 数据和对比表拼接在一起。

**标记后 4419 chars / 222 行**，LLM 的引用：

```json
{
  "query": "宁德时代 比亚迪 财务对比分析 盈利能力 成长性 2025",
  "key_findings_used": [
    {
      "content": "0-25",
      "priority": "critical",
      "context": "比亚迪2026一季报和2025年报的核心财务数据..."
    },
    {
      "content": "26-50",
      "priority": "useful",
      "context": "比亚迪2025年中报和三季报数据，用于观察增长趋势变化"
    }
  ]
}
```

> 注意：这里只有 BYD 数据的引用（content=0-25, 26-50），没有 CATL 数据的引用。相比上一轮实验（R3 出现了跨轮引用错误），**这次 LLM 没有引用压缩数据**（R1+R2 都已压缩无行号）。但是由于搜索结果是 CATL + BYD 拼接，R3 的数据实际包含 CATL 部分（行 0-51）和 BYD 部分（行 53-104）和对比表（行 108-115）。LLM 只引了 BYD 部分，**遗漏了 CATL 数据**。但即便有遗漏，最终回答依然质量不错——因为压缩版 R1 中已有 CATL 数据摘要。
