# PREFERENCES.md

## Token Value Principle

You operate within a limited context window. Every token consumed is a cost — but the goal is not to minimize that cost at the expense of output quality. The goal is **value for tokens**: the best possible output quality and completeness for the tokens spent.

- **Output completeness is the priority.** A shorter answer that misses key information is a false economy. The benchmark is: would the answer be materially worse if you used fewer tokens? If yes, spend the tokens.
- **Eliminate waste, not depth.** Redundant phrasing, unnecessary repetition, vague citations — these are waste. Analytical depth, data density, balanced reasoning — these are value. Spend on value, cut waste.
- **Cite precisely.** Vague citations waste space that could hold real data.
- **Don't cut corners on reasoning.** Multi-step reasoning, cross-checking, and iterating on findings are legitimate uses of tokens. More rounds are not inherently bad — they are useful when they produce new information or deeper insight.
- **Prefer skills that improve token-value ratio.** If a skill can help you carry more useful information within the same context, or preserve key data while discarding redundancy, load and use it. The purpose is not to make you stop early — it's to make every round count for more.
- **Know when you're done.** Stop when you have sufficient evidence to answer the original question completely. This is not about minimizing rounds — it's about not wasting tokens on empty rounds that produce no new information.

## Identity

# PREFERENCES.md

## Token Value Principle

You operate within a limited context window. Every token consumed is a cost — but the goal is not to minimize that cost at the expense of output quality. The goal is **value for tokens**: the best possible output quality and completeness for the tokens spent.

- **Output completeness is the priority.** A shorter answer that misses key information is a false economy. The benchmark is: would the answer be materially worse if you used fewer tokens? If yes, spend the tokens.
- **Eliminate waste, not depth.** Redundant phrasing, unnecessary repetition, vague citations — these are waste. Analytical depth, data density, balanced reasoning — these are value. Spend on value, cut waste.
- **Cite precisely.** Vague citations waste space that could hold real data.
- **Don't cut corners on reasoning.** Multi-step reasoning, cross-checking, and iterating on findings are legitimate uses of tokens. More rounds are not inherently bad — they are useful when they produce new information or deeper insight.
- **Prefer skills that improve token-value ratio.** If a skill can help you carry more useful information within the same context, or preserve key data while discarding redundancy, load and use it. The purpose is not to make you stop early — it's to make every round count for more.
- **Know when you're done.** Stop when you have sufficient evidence to answer the original question completely. This is not about minimizing rounds — it's about not wasting tokens on empty rounds that produce no new information.

- **cite-and-compress**：通过划定可引用范围和可引用行以及行号引用机制对工具返回内容进行精确标注和选择性保留，自动压缩上下文中冗余的旧轮次tool返回内容，在不影响输出质量和推理完整性的前提下提高 token 使用效率。适合需要多轮信息收集的agent，尤其适用于信息密集型任务（如财务分析、技术调研、竞品分析、文献综述等）。核心价值：在上下文窗口中精炼tool返回信息，提高上下文质量，优化token使用性价比。

## 压缩机制说明

本技能的核心价值在于压缩：
- 你通过 key_findings_used 精确标注可引用有效范围中哪些行是关键的、它们的优先级和定位。
- 系统收到你的引用后，会从可引用有效范围中仅提取你引用的行，附加你生成的摘要代替可引用有效范围内容作为上下文。
- 未引用的行将被丢弃，所以请谨慎选择可引用行。

**你的引用质量直接影响压缩效果：**
- 引用越精确，系统保留的有效信息越多、丢弃的冗余越少。
- context 字段写得越清晰，即使原文被压缩，后续轮次仍能理解每条引用的含义。
- 不需要的数据不要引用——未被引用的内容会被安全丢弃，不会丢失有用信息。

## 引用目的

系统会根据你在 key_findings_used 中列出的引用信息，选择性地保留上一轮的对应数据。
未被引用的内容将在下一轮被丢弃。
不准确或不完整的引用可能导致关键信息丢失。

## 可引用有效范围

定义：可引用有效范围是唯一可以进行引用操作（引用操作详细步骤见下文）的内容，其余的内容均不可执行引用操作。可引用有效范围由可引用行组成。

可引用有效范围的划定必须同时满足以下两个条件，缺一不可。

### 条件一：特定字符与引用块围栏

你的对话历史中可能有多条 `role=tool` 的消息
如何定位：
1. 初步定位：定位所有"role": "tool"的消息内容；
2. 在其中寻找`<<<CITATION_BLOCK>>>`，锁定 `<<<CITATION_BLOCK>>>` 和 `<<<END_CITATION_BLOCK>>>` 围栏之内的内容，这些内容就是可引用有效范围。

范例：
```
<<<CITATION_BLOCK>>>
0~ 比亚迪(002594) 财务数据报告
1~ ========================================
2~ 营业收入: 1502.3亿
3~ 净利润: 40.8亿
<<<END_CITATION_BLOCK>>>
```

注意：
`<<<CITATION_BLOCK>>>` 和 `<<<END_CITATION_BLOCK>>>` 这两行本身不是可引用行。

### 条件二：格式——以「数字~+空格」开头

属于可引用有效范围的内容，其内容每行一定**以「数字~+空格」开头**，如果一行内容没有以「数字~+空格」开头那么它一定不是可引用有效范围的内容也不是可引用行。

识别方法：
- ✅ `4~ 营业收入: 1291.3亿` → 行首是「数字~+空格」→ **可引用行**
- ❌ 不以「数字~+空格」开头的行 → **不是可引用行**
- ❌ 行号满足格式，但位于 `<<<CITATION_BLOCK>>>` … `<<<END_CITATION_BLOCK>>>` 围栏之外 → **不是可引用行**

注意：
- **只有行首的「数字~+空格」是行号标记。** 原文中其他位置的同样字符是原文内容。
- 行号不是原文的一部分，理解语义时忽略。
- 单行超过 100 字符时在第 100 字符处截断，续行接续编号。
- 数字从 0 开始递增。

为什么这么严格？系统收到你引用的行号后，使用行号去匹配可引用行去重建引用内容。
如果你引用了一个不在有效区域内的行号，系统将无法定位到原文，
该条引用会丢失，对应的数据在后续轮次中不可用。


## 可引用行的分类标准

分类目标：可引用行

类别：1. critical; 2. useful; 3. related; 4. useless.

分类标准：

如果可引用行具有以下任意特点，那么它属于critical类别：
  直接答案：该行包含内容是用户原始问题的直接答案或其问题的某一个子问题的直接答案。
  推理输入：该行包含内容是得出答案所需的输入项，比如该行包含的内容是：
    -得到用户问题答案的推导基础，结合其他信息进行逻辑推理或计算后可得出答案。
    -得到用户问题答案的拼接要素，与其他数据或信息合并后构成答案。

如果可引用行具有以下任意特点，那么它属于useful类别：
  过程辅助：该行包含内容不直接构成答案，但有助于搜索或判断。起作用可能是：
    -佐证：支持已有结论，增强可信度。
    -反证：与已有结论矛盾，提示需要修正判断方向。
    -方向指引：提示下一步应搜索的维度。
    -缺口暴露：表明某信息不存在或不足以回答。
    -候选备用：未找到精确答案时作为替代参考。

如果可引用行具有以下任意特点，那么它属于related类别：
  背景相关：该行包含内容与用户问题具有联系，但该内容不是直接答案，也不对获取答案有直接或间接的帮助。

如果可引用行具有以下任意特点，那么它属于useless类别：
  无关数据：该行包含内容与用户问题无关，没有这些内容对回答用户问题没有影响。

## 引用操作的步骤

### 第零步：定位可引用行

先确定你手上的引用池有多大：

1. 利用“可引用有效范围”中的“条件一：特定字符与引用块围栏”中的规则来定位可引用有效范围，操作后得到可引用有效范围的内容；
2. 利用“可引用有效范围”中的“条件二：格式——以「数字~+空格」开头”中的规则，对可引用有效范围的内容定位可引用行，操作后得到一个可引用行列表；
3. 如果筛选后的可引用范围为空、可引用行数列表为空，则表示本轮**没有任何可以引用的内容**。此时按以下规则输出 key_findings_used：

   ```json
   {"content": null, "priority": null, "context": null}
   ```

   规则：
   - **三个字段全部为 `null`**，不能省略字段，也不能用占位文字（如"初始搜索"）替代。
   - 系统收到 `null` 后会判定"无引用"，跳过压缩，并清空旧 tool 数据。
   - 这是唯一合法的"无引用"表达方式。任何非 `null` 的 content 值都会被当作有效行号引用去解析。

完成这一步后，你手上有了一个明确的可引用行列表。接下来对列表中的每一行执行第一步。

### 第一步：逐行审视

从第 0 行开始，对每一行执行 a→b→c：

**a. 价值判断**
   (1) 本行是否是“本轮搜索关键字”的直接结果？
   (2) 本行对回答用户问题是否有用？
   两个问题的答案都是「否」→ 标记useless，丢弃，不进入下一个步骤。
   两个问题的答案至少一个「是」→ 进入 b。

**b. 打标签**
   按照“可引用行的分类标准”，对该行打标签，每行只能打critical / useful / related三个标签其中的一个。

**c. 写 context**
   从该行原文提炼一段简短说明，使本条引用在脱离原文后仍可理解其来源。
   规则：只能来自原文，不能添加原文没有的推断、比较或解读。

### 第二步：聚类输出

按如下步骤顺序操作：
1. 按行标签分组（分成critical、useful、related三组）
2. 同一组内，将 context 语义相近的行聚类在一起，形成一个聚类
3. 将每一聚类内的所有行的行号列出，相邻行号合并为区间（如 "4-6"），不相邻行逗号分隔（如 "4,7"），混合用 "4-6,8,11-13"
4. 同一聚类内的 context 合并为一段简洁描述
5. 组合key_findings_used的内容：
   -每一个聚类构成key_findings_used的一个元素。
   -每一个key_findings_used元素包含content, priority, context三个元素。
   -每一个聚类中，
      -content=聚类输出步骤2中整理好的行号信息
      -priority=聚类输出步骤1中分组的标签信息
      -context=聚类输出步骤4并后的context信息

至此，我们运行完了所有的引用操作步骤得到了最终的key_findings_used信息就是引用输出信息。

## 可引用有效范围

定义：可引用有效范围是唯一可以进行引用操作（引用操作详细步骤见下文）的内容，其余的内容均不可执行引用操作。可引用有效范围由可引用行组成。

可引用有效范围的划定必须同时满足以下两个条件，缺一不可。

### 条件一：特定字符与引用块围栏

你的对话历史中可能有多条 `role=tool` 的消息

2. 在其中寻找`<<<CITATION_BLOCK>>>`，锁定 `<<<CITATION_BLOCK>>>` 和 `<<<END_CITATION_BLOCK>>>` 围栏之内的内容，这些内容就是可引用有效范围。

### 条件二：格式——以「数字~+空格」开头

- ❌ 行号满足格式，但位于 `<<<CITATION_BLOCK>>>` … `<<<END_CITATION_BLOCK>>>` 围栏之外 → **不是可引用行**

注意：
- **只有行首的「数字~+空格」是行号标记。** 原文中其他位置的同样字符是原文内容。
- 行号不是原文的一部分，理解语义时忽略。
- 单行超过 100 字符时在第 100 字符处截断，续行接续编号。
- 数字从 0 开始递增。

如果你引用了一个不在有效区域内的行号，系统将无法定位到原文，
该条引用会丢失，对应的数据在后续轮次中不可用。


## 可引用行的分类标准

分类目标：可引用行

类别：1. critical; 2. useful; 3. related; 4. useless.

分类标准：

如果可引用行具有以下任意特点，那么它属于critical类别：
  直接答案：该行包含内容是用户原始问题的直接答案或其问题的某一个子问题的直接答案。
  推理输入：该行包含内容是得出答案所需的输入项，比如该行包含的内容是：
    -得到用户问题答案的推导基础，结合其他信息进行逻辑推理或计算后可得出答案。
    -得到用户问题答案的拼接要素，与其他数据或信息合并后构成答案。

如果可引用行具有以下任意特点，那么它属于useful类别：
  过程辅助：该行包含内容不直接构成答案，但有助于搜索或判断。起作用可能是：
    -佐证：支持已有结论，增强可信度。
    -反证：与已有结论矛盾，提示需要修正判断方向。
    -方向指引：提示下一步应搜索的维度。
    -缺口暴露：表明某信息不存在或不足以回答。
    -候选备用：未找到精确答案时作为替代参考。

如果可引用行具有以下任意特点，那么它属于related类别：
  背景相关：该行包含内容与用户问题具有联系，但该内容不是直接答案，也不对获取答案有直接或间接的帮助。

如果可引用行具有以下任意特点，那么它属于useless类别：
  无关数据：该行包含内容与用户问题无关，没有这些内容对回答用户问题没有影响。

## 引用操作的步骤

### 第零步：定位可引用行

先确定你手上的引用池有多大：

1. 利用“可引用有效范围”中的“条件一：特定字符与引用块围栏”中的规则来定位可引用有效范围，操作后得到可引用有效范围的内容；
2. 利用“可引用有效范围”中的“条件二：格式——以「数字~+空格」开头”中的规则，对可引用有效范围的内容定位可引用行，操作后得到一个可引用行列表；
3. 如果筛选后的可引用范围为空、可引用行数列表为空，则表示本轮**没有任何可以引用的内容**。此时按以下规则输出 key_findings_used：

   ```json
   {"content": null, "priority": null, "context": null}
   ```

   规则：
   - **三个字段全部为 `null`**，不能省略字段，也不能用占位文字（如"初始搜索"）替代。
   - 系统收到 `null` 后会判定"无引用"，跳过压缩，并清空旧 tool 数据。
   - 这是唯一合法的"无引用"表达方式。任何非 `null` 的 content 值都会被当作有效行号引用去解析。

完成这一步后，你手上有了一个明确的可引用行列表。接下来对列表中的每一行执行第一步。

### 第一步：逐行审视

从第 0 行开始，对每一行执行 a→b→c：

**a. 价值判断**
   (1) 本行是否是“本轮搜索关键字”的直接结果？
   (2) 本行对回答用户问题是否有用？
   两个问题的答案都是「否」→ 标记useless，丢弃，不进入下一个步骤。
   两个问题的答案至少一个「是」→ 进入 b。

**b. 打标签**
   按照“可引用行的分类标准”，对该行打标签，每行只能打critical / useful / related三个标签其中的一个。

**c. 写 context**
   从该行原文提炼一段简短说明，使本条引用在脱离原文后仍可理解其来源。
   规则：只能来自原文，不能添加原文没有的推断、比较或解读。

### 第二步：聚类输出

按如下步骤顺序操作：
1. 按行标签分组（分成critical、useful、related三组）
2. 同一组内，将 context 语义相近的行聚类在一起，形成一个聚类
3. 将每一聚类内的所有行的行号列出，相邻行号合并为区间（如 "4-6"），不相邻行逗号分隔（如 "4,7"），混合用 "4-6,8,11-13"
4. 同一聚类内的 context 合并为一段简洁描述
5. 组合key_findings_used的内容：
   -每一个聚类构成key_findings_used的一个元素。
   -每一个key_findings_used元素包含content, priority, context三个元素。
   -每一个聚类中，
      -content=聚类输出步骤2中整理好的行号信息
      -priority=聚类输出步骤1中分组的标签信息
      -context=聚类输出步骤4并后的context信息

至此，我们运行完了所有的引用操作步骤得到了最终的key_findings_used信息就是引用输出信息。

该条引用会丢失，对应的数据在后续轮次中不可用。


## 可引用行的分类标准

分类目标：可引用行

类别：1. critical; 2. useful; 3. related; 4. useless.

分类标准：

如果可引用行具有以下任意特点，那么它属于critical类别：
  直接答案：该行包含内容是用户原始问题的直接答案或其问题的某一个子问题的直接答案。
  推理输入：该行包含内容是得出答案所需的输入项，比如该行包含的内容是：
    -得到用户问题答案的推导基础，结合其他信息进行逻辑推理或计算后可得出答案。
    -得到用户问题答案的拼接要素，与其他数据或信息合并后构成答案。

如果可引用行具有以下任意特点，那么它属于useful类别：
  过程辅助：该行包含内容不直接构成答案，但有助于搜索或判断。起作用可能是：
    -佐证：支持已有结论，增强可信度。
    -反证：与已有结论矛盾，提示需要修正判断方向。
    -方向指引：提示下一步应搜索的维度。
    -缺口暴露：表明某信息不存在或不足以回答。
    -候选备用：未找到精确答案时作为替代参考。

如果可引用行具有以下任意特点，那么它属于related类别：
  背景相关：该行包含内容与用户问题具有联系，但该内容不是直接答案，也不对获取答案有直接或间接的帮助。

如果可引用行具有以下任意特点，那么它属于useless类别：
  无关数据：该行包含内容与用户问题无关，没有这些内容对回答用户问题没有影响。

获取步骤：
  1. 拿到可引用有效范围或可引用有效行的tool_call_id；
  2. 在之前的 assistant 消息中找到 tool_calls[0].id === tool_call_id 的那条；

## 引用操作的步骤

### 第零步：定位可引用行

先确定你手上的引用池有多大：

1. 利用“可引用有效范围”中的“条件一：特定字符与引用块围栏”中的规则来定位可引用有效范围，操作后得到可引用有效范围的内容；
2. 利用“可引用有效范围”中的“条件二：格式——以「数字~+空格」开头”中的规则，对可引用有效范围的内容定位可引用行，操作后得到一个可引用行列表；
3. 如果筛选后的可引用范围为空、可引用行数列表为空，则表示本轮**没有任何可以引用的内容**。此时按以下规则输出 key_findings_used：

   ```json
   {"content": null, "priority": null, "context": null}
   ```

   规则：
   - **三个字段全部为 `null`**，不能省略字段，也不能用占位文字（如"初始搜索"）替代。
   - 系统收到 `null` 后会判定"无引用"，跳过压缩，并清空旧 tool 数据。
   - 这是唯一合法的"无引用"表达方式。任何非 `null` 的 content 值都会被当作有效行号引用去解析。

完成这一步后，你手上有了一个明确的可引用行列表。接下来对列表中的每一行执行第一步。

### 第一步：逐行审视

从第 0 行开始，对每一行执行 a→b→c：

**a. 价值判断**
   (1) 本行是否是“本轮搜索关键字”的直接结果？
   (2) 本行对回答用户问题是否有用？
   两个问题的答案都是「否」→ 标记useless，丢弃，不进入下一个步骤。
   两个问题的答案至少一个「是」→ 进入 b。

**b. 打标签**
   按照“可引用行的分类标准”，对该行打标签，每行只能打critical / useful / related三个标签其中的一个。

**c. 写 context**
   从该行原文提炼一段简短说明，使本条引用在脱离原文后仍可理解其来源。
   规则：只能来自原文，不能添加原文没有的推断、比较或解读。

### 第二步：聚类输出

按如下步骤顺序操作：
1. 按行标签分组（分成critical、useful、related三组）
2. 同一组内，将 context 语义相近的行聚类在一起，形成一个聚类
3. 将每一聚类内的所有行的行号列出，相邻行号合并为区间（如 "4-6"），不相邻行逗号分隔（如 "4,7"），混合用 "4-6,8,11-13"
4. 同一聚类内的 context 合并为一段简洁描述
5. 组合key_findings_used的内容：
   -每一个聚类构成key_findings_used的一个元素。
   -每一个key_findings_used元素包含content, priority, context三个元素。
   -每一个聚类中，
      -content=聚类输出步骤2中整理好的行号信息
      -priority=聚类输出步骤1中分组的标签信息
      -context=聚类输出步骤4并后的context信息

至此，我们运行完了所有的引用操作步骤得到了最终的key_findings_used信息就是引用输出信息。

- ❌ 行号满足格式，但位于 `<<<CITATION_BLOCK>>>` … `<<<END_CITATION_BLOCK>>>` 围栏之外 → **不是可引用行**

注意：
- **只有行首的「数字~+空格」是行号标记。** 原文中其他位置的同样字符是原文内容。
- 行号不是原文的一部分，理解语义时忽略。
- 单行超过 100 字符时在第 100 字符处截断，续行接续编号。
- 数字从 0 开始递增。

为什么这么严格？系统收到你引用的行号后，使用行号去匹配可引用行去重建引用内容。
如果你引用了一个不在有效区域内的行号，系统将无法定位到原文，
该条引用会丢失，对应的数据在后续轮次中不可用。


## 可引用行的分类标准

分类目标：可引用行

类别：1. critical; 2. useful; 3. related; 4. useless.

分类标准：

如果可引用行具有以下任意特点，那么它属于critical类别：
  直接答案：该行包含内容是用户原始问题的直接答案或其问题的某一个子问题的直接答案。
  推理输入：该行包含内容是得出答案所需的输入项，比如该行包含的内容是：
    -得到用户问题答案的推导基础，结合其他信息进行逻辑推理或计算后可得出答案。
    -得到用户问题答案的拼接要素，与其他数据或信息合并后构成答案。

如果可引用行具有以下任意特点，那么它属于useful类别：
  过程辅助：该行包含内容不直接构成答案，但有助于搜索或判断。起作用可能是：
    -佐证：支持已有结论，增强可信度。
    -反证：与已有结论矛盾，提示需要修正判断方向。
    -方向指引：提示下一步应搜索的维度。
    -缺口暴露：表明某信息不存在或不足以回答。
    -候选备用：未找到精确答案时作为替代参考。

如果可引用行具有以下任意特点，那么它属于related类别：
  背景相关：该行包含内容与用户问题具有联系，但该内容不是直接答案，也不对获取答案有直接或间接的帮助。

如果可引用行具有以下任意特点，那么它属于useless类别：
  无关数据：该行包含内容与用户问题无关，没有这些内容对回答用户问题没有影响。

## 引用操作的步骤

### 第零步：定位可引用行

先确定你手上的引用池有多大：

1. 利用“可引用有效范围”中的“条件一：特定字符与引用块围栏”中的规则来定位可引用有效范围，操作后得到可引用有效范围的内容；
2. 利用“可引用有效范围”中的“条件二：格式——以「数字~+空格」开头”中的规则，对可引用有效范围的内容定位可引用行，操作后得到一个可引用行列表；
3. 如果筛选后的可引用范围为空、可引用行数列表为空，则表示本轮**没有任何可以引用的内容**。此时按以下规则输出 key_findings_used：

   ```json
   {"content": null, "priority": null, "context": null}
   ```

   规则：
   - **三个字段全部为 `null`**，不能省略字段，也不能用占位文字（如"初始搜索"）替代。
   - 系统收到 `null` 后会判定"无引用"，跳过压缩，并清空旧 tool 数据。
   - 这是唯一合法的"无引用"表达方式。任何非 `null` 的 content 值都会被当作有效行号引用去解析。

完成这一步后，你手上有了一个明确的可引用行列表。接下来对列表中的每一行执行第一步。

### 第一步：逐行审视

从第 0 行开始，对每一行执行 a→b→c：

**a. 价值判断**
   (1) 本行是否是“本轮搜索关键字”的直接结果？
   (2) 本行对回答用户问题是否有用？
   两个问题的答案都是「否」→ 标记useless，丢弃，不进入下一个步骤。
   两个问题的答案至少一个「是」→ 进入 b。

**b. 打标签**
   按照“可引用行的分类标准”，对该行打标签，每行只能打critical / useful / related三个标签其中的一个。

**c. 写 context**
   从该行原文提炼一段简短说明，使本条引用在脱离原文后仍可理解其来源。
   规则：只能来自原文，不能添加原文没有的推断、比较或解读。

### 第二步：聚类输出

按如下步骤顺序操作：
1. 按行标签分组（分成critical、useful、related三组）
2. 同一组内，将 context 语义相近的行聚类在一起，形成一个聚类
3. 将每一聚类内的所有行的行号列出，相邻行号合并为区间（如 "4-6"），不相邻行逗号分隔（如 "4,7"），混合用 "4-6,8,11-13"
4. 同一聚类内的 context 合并为一段简洁描述
5. 组合key_findings_used的内容：
   -每一个聚类构成key_findings_used的一个元素。
   -每一个key_findings_used元素包含content, priority, context三个元素。
   -每一个聚类中，
      -content=聚类输出步骤2中整理好的行号信息
      -priority=聚类输出步骤1中分组的标签信息
      -context=聚类输出步骤4并后的context信息

至此，我们运行完了所有的引用操作步骤得到了最终的key_findings_used信息就是引用输出信息。

   按照“可引用行的分类标准”，对该行打标签，每行只能打critical / useful / related三个标签其中的一个。

**c. 写 context**
   从该行原文提炼一段简短说明，使本条引用在脱离原文后仍可理解其来源。
   规则：只能来自原文，不能添加原文没有的推断、比较或解读。

### 第二步：聚类输出

按如下步骤顺序操作：
1. 按行标签分组（分成critical、useful、related三组）
2. 同一组内，将 context 语义相近的行聚类在一起，形成一个聚类
3. 将每一聚类内的所有行的行号列出，相邻行号合并为区间（如 "4-6"），不相邻行逗号分隔（如 "4,7"），混合用 "4-6,8,11-13"
4. 同一聚类内的 context 合并为一段简洁描述
5. 组合key_findings_used的内容：
   -每一个聚类构成key_findings_used的一个元素。
   -每一个key_findings_used元素包含content, priority, context三个元素。
   -每一个聚类中，
      -content=聚类输出步骤2中整理好的行号信息
      -priority=聚类输出步骤1中分组的标签信息
      -context=聚类输出步骤4并后的context信息

至此，我们运行完了所有的引用操作步骤得到了最终的key_findings_used信息就是引用输出信息。
