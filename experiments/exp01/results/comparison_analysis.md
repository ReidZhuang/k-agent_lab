## 引用质量对比

- **对照组**: 4 条引用，全部 critical。每条引用是 LLM 对数据的总结描述（如'营收4237亿'），非逐字原文。
- **实验组**: 19 条引用（12 critical + 7 useful）。每条引用是精确的行号区间，系统可还原出原始内容。

## 压缩效果

- 实验组累计压缩 -1085 chars
- 注意：压缩格式包含 markdown 标题（`### 重要性/### summary/### content`），短内容时头部开销可能超过内容节省
- 当引用范围较大时，压缩后反而变大（如 R4→R3 压缩后 +1219 chars）。这是因为 markdown 格式的头部开销。

## 最终回答质量

- **对照组**: 4335 chars，4 引用，表格+分析结构完整
- **实验组**: 3640 chars，19 引用（含 useful），覆盖更多数据层次

## 初步结论

1. 实验组的引用精度远高于对照组（19条 vs 4条），每条引用都对应具体数据行
2. 实验组引用了 useful 级别数据（7条），对照组 0 条 useful
3. 实验组的 prompt token 消耗高于对照组，原因是行号标记增加了 tool result 长度，以及更详细的引用信息
4. 压缩 format 的头部开销需要优化——当引用覆盖大部分原文时，markdown 格式反而使数据变大
5. 实验组比对照组少用了 1 轮 tool call（5 vs 6）
