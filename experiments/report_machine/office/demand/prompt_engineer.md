## 一、报告结构与内容要求的优化

**结构整体是好的，但有三个痛点：**

**1. 第一板块"基础行情"缺少两个最有价值的比较维度**

你列了涨跌幅、振幅、成交额，但 context 里其实提供了量比（0.9）和内外盘比（外盘3754903 vs 内盘4610826），这两个数字对判断午间卖压非常直接。TCL这个例子里，内盘 > 外盘，结合净流出1.35亿，可以直接判断主动抛压明显。但你的模板里没有要求列出这两个字段。

建议在第一板块加：
```
| 量比 | 0.9（温和缩量） |
| 内外盘比 | 外盘/内盘 = 81%（卖压偏强）|
```

**2. 第四板块"资金博弈"的来源和时效混乱**

你的模板列了"主力资金净流入（估算）"，context里其实有两套数据：
- 今日午间逐分钟资金流向：净流出1.35亿（实时，可信度高）
- 前一日日终资金细分（大单/中单/小单）：前一日数据

这两套时效不同，性质也不同——前者是今日实况，后者是昨日存量信号。模板里应当明确区分，不然读者搞不清哪个是今天的。

建议改为：
```
| 今日午间资金净流向 | 净流出1.35亿（逐分钟统计，242分钟） |
| 流入/流出分钟比 | 121分钟流入 / 119分钟流出（分歧激烈）|
```

## 二、Prompt 优化建议

**soul.md**：很好，角色定义清晰，原则简洁。无需修改。

**preference.md 的两个问题：**

第一，报告结构（7个板块）在preference.md里写了一遍，你的需求描述里又写了一遍（用模板形式），但两处的细节和叫法稍有不同（比如你写"一、基础行情"，preference写"个股分析"），会让LLM拼接时出现混乱。建议二选一：要么preference.md里只保留写作风格，把结构全部放到技能文件（skill）里；要么preference.md的结构部分和报告模板完全保持一致的标题名称。

第二，preference.md 里"市场概况"和"综合研判"两个章节在你的实际模板里已经改名为其他叫法，会造成LLM在两套命名之间摇摆。

**agent.md 有一个重要遗漏：**

你设置了最多8轮交互，但没有给LLM任何关于"读完所有数据后先做规划再行动"的明确指令。高质量的报告生成应该是：先通读所有数据+文章标题 → 判断哪些文章正文值得读 → 一次性批量调取 → 生成报告。但如果LLM在第一轮就开始写报告，它可能在还没调取关键正文的情况下就输出了。

建议在agent.md里加一段明确的工作规划指令：

```
## 工作规划（必须遵守）
在开始撰写报告前，请先完成以下步骤：
1. 通读所有 fetch_data 和 fetch_message 数据
2. 浏览所有文章标题和摘要，判断哪些文章对分析有实质帮助
3. 一次性批量调取所有判断有价值的文章正文（单次 tool call）
4. 所有信息收集完毕后，再开始撰写报告
```

## 三、Skill 加载 vs 上下文组装——哪个更好

**结论：做成 skill 文件加载更好，理由如下：**

你每天要生成多只股票的报告，上下文大小是首要成本。如果把报告模板（包括模板格式、7个板块的要求、所有占位符说明）都拼进 system prompt 的 user message 里，它会在每次调用里都出现一遍，并且和 fetch_data 这类动态数据混在一起，LLM 需要在更大的上下文里寻找指令，注意力会被稀释。

Skill 文件作为独立的 system 指令存在，有几个好处：
- LLM 在生成阶段对 skill 的注意力更稳定（system prompt 权重更高）
- 多只股票调用时，skill 文件内容不变，只有 context（fetch_data/fetch_message/articles）变化，方便追踪和排查输出质量问题
- 你可以独立迭代 skill 而不影响上下文构建逻辑

**实际组装方式建议：**
```
System message = soul.md + agent.md + preference.md + skill_noon_report.md
User message = fetch_data 数据 + fetch_message 数据 + articles 标题列表
```

## 四、固定内容 + 自由发挥的 Prompt 写法

在 skill 文件里，把要求分为两层，用视觉分隔线明确区分：

```markdown
## 【必须包含】固定结构（按以下模板严格输出）

[七个板块的模板，带具体字段要求]

---

## 【自由发挥】额外洞察（在固定结构之后补充）

在完成以上固定结构后，如果你在数据或资讯中发现了以下任何一类有证据支撑的信号，请在报告末尾"附：补充洞察"部分自由发挥：

**可以补充的方向（必须有数据或资讯来源作为证据）：**
- 多板块排名交叉印证：如在某些板块跑赢、另一些跑输，说明背后的逻辑差异
- 资金异动信号：如大买盘时间点与价格低点的关系（是否有人抄底）
- 中长期价值线索：**仅在资讯中有具体业绩数据、合同金额、产能规划等可验证信息时才写**，否则留空
- 风险叠加：如外部（美股半导体暴跌）与内部（大单持续流出）风险信号同时出现

**严禁补充的内容：**
- 无数据支撑的趋势预测
- 模糊表述（"未来可能"、"或将迎来"等）
- 任何形式的买卖建议
```

这样做的效果是：LLM知道固定内容要完整，自由部分有明确的激发方向，但也有清晰的禁区。

## 五、30秒摘要第二部分的写法建议

你的第一部分结构已经很清晰了（数据事实+资讯总结）。第二部分留给LLM自由发挥，建议在 skill 文件里给LLM以下方向提示，而不是完全不限制：

```markdown
## 七、30秒摘要

**第一部分（固定格式）：**
{{company_name}} 今天上午 {{涨跌}}X.X%，[跑赢/跑输]{{所属主要板块}}X.X个百分点，
[有/无]新驱动，[有/无]风险信号。资金[净流入/净流出]X.XX亿。
[突破/贴近/位于下方] MA{{N}}（{{MA值}}元）。
{{如有驱动或风险相关资讯，一句话总结}}

**第二部分（自由发挥，30-50字，不与第一部分重复）：**
从以下方向中选择最值得点出的一个或两个写：
- 今日行情的结构特点（如"放量但未破位"、"缩量企稳"等有数据支撑的描述）
- 最需要关注的一个尾盘变量或明日观察点
- 如有外部宏观事件与该股关联明确，指出其潜在影响方向
- 如无特别值得点出的信息，此部分可以不写

不写的判断标准：如果只能写出模糊表述，宁可留空。
```

这样的设计让第二部分有方向感但不僵化，LLM 会根据实际数据决定写什么——在 TCL 这个例子里，它应该会写"外围美股半导体板块连续重挫叠加国内全面杀跌背景下，个股跌幅显著小于所属光伏/消费电子板块，抗跌性值得关注"这类有实质价值的判断，而不是泛泛而谈。
