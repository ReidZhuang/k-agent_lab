# fetch_article_body

## 何时使用

- 仅当「相关新闻资讯列表」中某篇文章 `body_avail` 为"有",且仅凭标题+摘要无法判断其对分析的价值时
- 优先获取:直接关系到公司本身的(业绩/合同/增减持/监管)、含具体数据的、能解释今日涨跌的正文

## 何时禁用

- 资讯列表之外的文章
- `body_avail` 为"无"的文章
- 摘要已含足够信息(如业绩数字)时
- 同一事件多源报道,只取信息量最丰富的一篇,其余禁用
- 低相关噪音(行业泛闻/投资者问答/互动平台占位内容)

## 输入参数

`articles`: 对象(object),键=来源引擎名,值=文章 ID 数组。

- 引擎名(字符串,枚举):`thsnews` / `sinafin` / `thsfin` / `baidufin` / `juchao` / `qnainfo`——必须原样使用列表中 `**来源: xxx**` 标注的引擎名
- ID 数组(字符串数组):如 `["a_01", "a_02"]`——必须原样使用该引擎下 `ID:` 字段的值
- **禁止**:ID 加引擎前缀(如 `thsnews_a_01`)、拼接、改名
- 同一引擎多篇文章合并为一个数组项;单次调用尽量批量(多引擎多篇)

示例:

```json
{"articles": {"thsnews": ["a_01", "a_02", "a_05"], "sinafin": ["a_01"]}}
```

## 返回格式(结构固定)

按调用顺序逐引擎返回,每个引擎一节:

```
### {engine} 正文

**文章 {id}**
标题:{title}
发布日期:{date}
{正文全文}
```

## 错误与异常

- 某篇获取失败(返回空):按该篇标题和摘要自行判断,不重试、不编造正文
- 某 ID 无效:仅该 ID 返回空,不影响同批其他 ID
- 诊断:结果中缺失某引擎分组=该引擎全部失败,按摘要分析即可,报告中不必说明
