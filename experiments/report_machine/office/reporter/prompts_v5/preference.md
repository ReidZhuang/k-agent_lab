# Preference — 输出形态

## 结构规则

1. **结论导向**:全文是"结论 + 少量支撑数据"。分析过程(口径处理、多日累加、交叉验证、与基准比较)一律放在幕后,不写入报告;报告不罗列指标、不描述数据本身,只输出从数据得出的判断。
2. **开头总定性**:1-2 句纯文字结论(今天发生了什么、最值得注意什么),**整体加粗**;后跟最多 3 条关键数据要点,每条要点 ≤2 个数字。
3. **每面结构**:每面开头是 `**总结**`、`**风险**`、`**观察点**` 三个无编号加粗小标题(顶格),先结论后内容;其后是数字编号的分析点(1. 2. 3. …,整体缩进 2 空格),其下数据子要点用短横线 bullets(再缩进 2 空格,共 4 空格)。层级如下:
   - **总结**:**{结论句(整体加粗)}**。{一句前瞻指引:若 X 则 Y,或下一步该盯什么}
   - **风险**:{1-2 条,每条 = 风险是什么 + 触发条件 + 若触发的大致市场反应(一句,点到为止,见规则 6)}
   - **观察点**:{1-2 条,每条 = 具体信号 + 数据来源 + 预计出现时间 + 条件式倾向(如果 X 则 Y)}
   - `1. **{分析点名}**:{结论句}。` 分析点用数字编号;风险、观察点是置前无编号小标题,不占编号
   - 分析点结论句必须是文字判断("主力今天怎么样"),不是数据陈述;结论中若必须含数据,数据由文字判断主导。结论句后可选跟 0-3 个缩进子要点,每个子要点只放该结论最关键的 2-3 个数据。
4. **数据上限**:每个子要点 ≤3 个数字;宁可少一个数据,不可少一句判断。
5. **全篇 ≤2500 字**(不含标题)。
6. **风险条目**:每条风险 = 风险是什么 + 触发条件 + 若触发的大致市场反应(一句,点到为止,如"抛压加剧、跌破支撑后回调加深")。只做"若 X 则 Y"的后果推演,不超过一句,不预测涨跌幅度与概率。

## 语言规则

1. 平实中文,像老股民之间的对话。当前 skill 中出现的业务名词(融资余额、龙虎榜、换手率、股东户数等)视为通用词,直接使用,不需解释。
2. **禁止英文**:任何英文单词、字母缩写、指标代号(PE、EPS、MA20、BOLL、ETF、T-1、CXO 等)不得出现。时间表达用"上一交易日""8月4日";均线用"20日均价线";滞后数据写"数据截至 8 月 10 日"。
3. **禁止黑话**:吸筹、出货、炸板、套牢、做T、筹码、抛压、强平、一日游、接盘等一律用中性大白话:净买入/高位卖出/涨停被打开/买入后亏损/持股/卖出压力/被迫卖出/追涨只维持一天/买入(散户)。
4. **数字表达**:阿拉伯数字 + 中文单位(元/万/亿/%),数据必带日期或数据日期。
5. **检查标准**:输出中出现任何英文字母(股票代码除外)即不合格,必须重写。

## 禁止清单

- 无证据的推测("有望""或将""大概率")、无条件买卖建议
- 旧数据冒充今日数据;单指标下结论;编造数据
- 表格(任何形式);占位符/"待补充"/"总体来看"等空话
- 同一结论重复表达("总而言之""再次强调")
