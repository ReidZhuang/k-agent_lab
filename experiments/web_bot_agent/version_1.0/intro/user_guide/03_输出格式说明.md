# 输出格式说明

`/poll` 返回的完整结果结构取决于请求时的 `mode`。

---

## segments 模式（默认）

### articles — 文章列表

以 `article_id`（如 `a_01`、`a_02`）为 key 的字典。

```json
"articles": {
  "a_01": {
    "title": "2025年中国信创产业生态发展报告",
    "url": "https://example.com/article/123",
    "date": "2025-06-15",
    "snippet": "本报告全面评估中国信息技术应用创新产业在操作系统、数据库...",
    "source": "example.com",
    "charnum": 8562,
    "segments": [
      {"id": "s1", "charnum": 1234},
      {"id": "s2", "charnum": 2456}
    ]
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | string | 文章标题 |
| `url` | string | 原文链接 |
| `date` | string | 发布日期 |
| `snippet` | string | 搜索结果摘要 |
| `source` | string | 来源网站域名 |
| `charnum` | number | 文章总字符数 |
| `segments` | array | 该文章的分组列表 |

### segments — 全部分组要点

以 `"{article_id}_{segment_id}"`（如 `a_01_s1`）为 key 的字典。

```json
"segments": {
  "a_01_s1": {
    "article_id": "a_01",
    "point": "信创产业市场规模与增长趋势",
    "summary": "中国信创产业规模快速增长，2024年达1.8万亿元...",
    "charnum": 1234,
    "keywords": "信创产业+市场规模+国产化率"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `article_id` | string | 所属文章 ID |
| `point` | string | 核心要点（LLM 生成） |
| `summary` | string | 内容概括（LLM 生成） |
| `charnum` | number | 该分组原文字符数 |
| `keywords` | string | 关键字（可选） |

---

## summary 模式

### articles — 文章列表

```json
"articles": {
  "a_01": {
    "title": "2025年中国信创产业生态发展报告",
    "url": "https://example.com/article/123",
    "date": "2025-06-15",
    "snippet": "...",
    "source": "example.com",
    "charnum": 8562,
    "mode": "summary",
    "summary": "本文全面评估了中国信创产业在操作系统、数据库等核心领域的国产化替代进展...（LLM统一概括）",
    "summary_relevant": [
      "本部分内容与搜索词「信创产业 国产替代 2025」相关...（块1相关摘要）",
      "本文分析了开发者生态、技术瓶颈和未来趋势...（块2相关摘要）"
    ],
    "key_points": [
      "信创产业规模快速增长，预计2025年将突破2.2万亿元。",
      "国产化替代面临挑战，尤其在高端芯片和工业软件领域。",
      "开发者规模持续壮大，年轻开发者占比高，一线城市集中。",
      "预计2030年信创市场规模将突破5万亿元，国产化率将超过80%。"
    ],
    "segments": []
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `mode` | string | 固定为 `"summary"` |
| `summary` | string | 文章整体概括（多块时由 LLM 合并各块客观概括生成） |
| `summary_relevant` | array[string] | 与搜索词相关的内容摘要（各块硬合并，去重） |
| `key_points` | array[string] | 核心要点列表（各块硬合并，去重） |
| `segments` | array | summary 模式固定为 `[]` |

### 生成逻辑（多块时）

```
客观概括 → LLM 合并 → summary（一段连贯文本）
相关摘要 → 硬合并（去重）→ summary_relevant[]
核心要点 → 硬合并（去重）→ key_points[]
```

### segments

summary 模式下 `segments` 为空 `{}`。

---

## 两种模式对比

| 维度 | segments 模式 | summary 模式 |
|---|---|---|
| 输出粒度 | 按段落分组，多组/文章 | 整篇一个摘要+若干要点 |
| `articles[].segments` | 分组列表 | `[]` |
| `segments{}` | 每组要点/概括/关键字 | `{}` |
| 额外字段 | 无 | `summary`, `summary_relevant`, `key_points` |
| 适用场景 | 需要按主题分段浏览 | 只想要整体概览和要点清单 |
