# 配置说明

配置文件位于 `config/config.json`，JSON 格式。

## 完整配置

```json
{
  "proxy": {
    "enabled": true,
    "http": "http://172.20.32.1:7890",
    "https": "http://172.20.32.1:7890"
  },
  "search": {
    "engine": "duckduckgo",
    "max_results": 5,
    "tool": "web-forager"
  },
  "extraction": {
    "primary": "trafilatura",
    "fallback": "readability",
    "output_format": "markdown",
    "include_images": false,
    "include_links": true,
    "timeout": 15
  },
  "ollama": {
    "endpoint": "http://localhost:11434",
    "models": {
      "default": "glm4:9b-chat-q4_K_M",
      "large": "glm4:9b-chat-q4_K_M"
    },
    "max_parallel": 4,
    "timeout": 120,
    "temperature": 0,
    "num_predict": 8192
  },
  "split": {
    "threshold_chars": 3000,
    "part_target_chars": 2000,
    "max_tokens": 2000
  },
  "session": {
    "ttl_minutes": 60
  }
}
```

## 配置项详解

### proxy — 代理设置

| 项 | 说明 |
|---|---|
| `enabled` | 是否启用代理 |
| `http` / `https` | HTTP/HTTPS 代理地址 |

> 搜索和网页抓取需要使用代理才能访问外网。如果无需代理，可将 `enabled` 设为 `false`（代码仍需代理时需手动修改 `core.py`）。

### ollama — 本地 LLM 设置

| 项 | 默认值 | 说明 |
|---|---|---|
| `endpoint` | `http://localhost:11434` | Ollama 服务地址 |
| `models.default` | `glm4:9b-chat-q4_K_M` | 推理用模型 |
| `max_parallel` | `4` | 并行推理数（受限于 GPU 显存） |
| `timeout` | `120` | LLM 请求超时（秒） |
| `temperature` | `0` | 生成温度。**设为 0 可保证输出确定性**，详见下方说明 |
| `num_predict` | `8192` | 最大生成 token 数，建议 4096-8192 |

> **temperature=0 的重要性**：设为 0 后，相同输入每次输出一致，方便调试。设为 >0 时 LLM 输出随机波动，分组结果不稳定。

> **num_predict**：不要设太小（如 1024），LLM 可能输出到一半被截断。8192 是安全值。

### split — 文本分块设置

| 项 | 默认值 | 说明 |
|---|---|---|
| `max_tokens` | `2000` | 每块的最大 token 数。超出此值的文章会被自动分块 |

> **分块逻辑**：当一篇文章的总 token 数 > `max_tokens` 时，按段落边界切分成多个块，分别送 LLM 分组后再合并。每块使用独立的局部段落编号（P1-Pn）。

### session — 会话设置

| 项 | 默认值 | 说明 |
|---|---|---|
| `ttl_minutes` | `60` | 会话过期时间（分钟）。超过此时间未查询的会话自动关闭 |

---

## 模型与显存参考

当前默认模型 `glm4:9b-chat-q4_K_M`：
- 参数量：9.4B
- 显存占用：约 6.3GB
- 上下文窗口：128K tokens
- **有效注意力窗口（实践经验）**：正文约 5,000 字 / 总 Prompt 约 6,500 字
- 量化等级：Q4_K_M（4-bit 混合精度）

> 如果文本超过 5,000 字，单独一次 LLM 调用可能出现注意力漂移（分组不完整、格式跑偏），系统会通过**自动分块**来规避此问题。
