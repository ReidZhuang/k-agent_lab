# 取数代码生成 Prompt 优化记录

## 优化原则

1. **去冗余**：只包含当前数据源必要信息，不列无关协议/数据源
2. **Python 判赢**：代码执行成功与否由 Python 实际执行结果决定，LLM 不判断
3. **不说废话**：不出现文件名（field.md/table.md/api.md），LLM 不需要知道来源
4. **无多余停止条件**：loop 自然终止（成功 / 达最大轮次）
5. **时间注明用途**：注入当前时间时必须说明"用于解析相对时间"

## 优化条目

### [P-01] 协议规则去冗余
- 问题：system prompt 的 SKILL.md 列出了所有协议规则，但一次只用一个
- 方案：从 system prompt 移除协议规则，改为在 task prompt 中按需注入

### [P-02] 执行结果由 Python 判定
- 问题：不应让 LLM 判断代码是否成功，Python 执行后直接返回成功/失败
- 方案：LLM 只负责生成代码 → Python 执行 → 成功则结束，失败则错误信息回喂

### [P-03] 不出现文件名
- 问题：prompt 中出现"field.md"、"table.md"等文件名，LLM 不理解
- 方案：直接嵌入内容，不要标注来源文件名

### [P-04] 停止条件精简
- 问题：无需显式列出停止条件，loop 机制控制
- 方案：AGENTS.md 只写工作流，不写"停止条件"章节

### [P-05] 时间字段说明用途
- 问题：当前时间注入但没说为什么
- 方案：注明"用于解析'今天/上午/下午'等相对时间"

### [P-06] 代码生成步骤明确
- 问题：没有给出组装代码的清晰步骤
- 方案：分步说明：确定主体→确定指标→确定表→确定范围→组装代码

### [P-07] 字段信息与表结构合并
- 问题：field.md 和 table.md 内容重复（都列字段），分开无意义
- 方案：合并为一个字段映射表，含字段名、类型、索引、说明、数据示例

### [P-08] 示例需标注代码结构
- 问题：示例只给代码，没标注各部分对应什么
- 方案：示例中标注哪部分是主体、字段、时间范围

### [P-09] 去中文化
- 问题：prompt 中同时出现中文字段名和英文列名，增加混乱
- 方案：只保留英文 column name，删除冗余中文名

### [P-10] 示例合并
- 问题：提取示例和 API 调用示例分开放置
- 方案：合并为一个完整示例，从 API 调用到字段提取到输出

### [P-11] System prompt 不含协议特定内容
- 问题：PREFERENCES.md 中出现 `requests.get(url, headers={...})` 等 HTTP 特定编码规范，但 Tushare/akshare 等 SDK 协议不需要
- 方案：system prompt（PREFERENCES.md、SKILL.md）只写通用规范。协议特定的 API 调用方式、编码要求全部放在 task prompt 中

### [P-12] 删除无用章节
- 问题："可用技能"列出 code_expert 但 LLM 不需要知道这个；"一般原则"内容是"每个数据源有独立 API 文档"等废话
- 方案：从 system prompt 中删除"可用技能"和"一般原则"章节

### [P-13] 数据源介绍精简
- 问题："名称: TuShare 日线行情（DS_TUSHARE_DAILY）"对 LLM 写代码没帮助
- 方案：只保留协议说明，删除数据源名称/ID 等无用描述

### [P-14] 查询条件结构化
- 问题：查询条件混在文本中，LLM 需要自己提取
- 方案：上游传入格式化为 `{'主体': [...], '指标': [...], '范围': {'时间': [...]}}`。prompt 直接引用这三个变量，明确告诉 LLM 它们对应代码中哪个位置

### [P-15] API 参数说明详细
- 问题：API 调用部分只列出函数名和参数名，没解释每个参数是什么、怎么用
- 方案：对每个参数写明含义、类型、是否必填、取值示例

### [P-16] 示例中分离硬编码与 LLM 生成部分
- 问题：示例中 import、token 设置等固定模板可以硬编码，不需要 LLM 每次重写
- 方案：示例中标注哪些部分是硬编码（模板注入），哪些需要 LLM 写。仅保留需要 LLM 动态生成的部分（如 pro.daily 的参数）

### [P-17] API 调用处示例去重
- 问题：API 调用段落有一个简短示例，末尾"示例"章节又有一个完整示例，重复
- 方案：API 调用段落只放函数签名和参数说明，不放代码示例。完整示例统一放在最后的"示例"章节

### [P-18] 生成步骤体现查询变量的代码定位
- 问题：生成步骤只说"组装请求、发送请求、提取字段"，没说查询主体/指标/范围在代码的哪里
- 方案：每一步都要写明查询变量对应代码中的什么位置。如"将查询主体 000001.SZ 填入 pro.daily(ts_code=...)"

### [P-19] 代码输出格式标准
- 问题：没有规定输出代码的格式标准（变量命名、错误处理、打印格式等）
- 方案：对输出的 Python 代码做统一格式要求（如变量名风格、必须处理空数据、打印格式）
