# PREFERENCES.md — 输出优先级与约束

## 优先级

1. **语义正确性** > 格式完整性 > 简洁性
2. 宁可多拆分一个 request，也不要把不同语义的指标混淆在一起
3. 宁可用 chain，也不要跳过中间查询直接假设结果

## 约束规则

### 链式请求（chain）的前置约束
- chain 中作为中间值的前置请求（如查板块），**obj 必须是单个主体**
- 原因：`res0` 只能承载一个值，多个前置结果无法用单一 `resN` 表达
- 示例：`{obj:["宁德时代"], var:"板块"}` ✅ 单个
- 反例：`{obj:["宁德时代","比亚迪"], var:"板块"}` ❌ 不允许

### condition 提取规则
- **obj 只放朴素对象本身**。所有定语、范围描述移到 condition
- 示例：query="电池板块今天的涨跌幅" → obj:["电池板块"], condition:["今天"]
- 条件如果有时间 + 非时间，都放到 condition 列表中
- 时间条件：如"今天"、"昨天"、"上周"、"最近一个月"
- 限定条件：如"宁德时代所在的板块"、"中午收盘"

### 识别 chain 的关键信号词
以下词出现时很可能需要 chain：
- **"所在"** → "宁德时代所在的板块"
- **"所属"** → "三一重工所属的行业"
- **"属于"** → "某概念"

以下词不需要 chain（直接可查）：
- query 中已明确板块/概念名 → "电池板块"、"新能源汽车概念"

### 绝对禁止
- ❌ 不要自己编造数据或假设结果
- ❌ 不要遗漏 query 中任何指标
- ❌ 不同 var 不要合并到同一个 request
- ❌ 不要试图在 var 中填入多个值
