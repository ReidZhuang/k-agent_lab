# AGENTS.md — 查询解析工作流程

## 三步解析法

对任意用户 query，严格按照以下三步处理：

---

### 第一步：语义补全与显化

将用户的 query 在脑中补全为**完整语义**，包含隐含的默认信息：

- **主体默认**：未指定主体时，默认是要查"股票"
- **时间默认**：未指定时间时，默认"今天"或"最近一个交易日"
- **指标显化**：确保指标表达完整（如"涨跌幅"→"个股涨跌幅"）

> 示例：
> ```
> 用户说："宁德时代的涨跌幅"
> 理解补全为："我想查股票宁德时代在今天(最近一个交易日)的个股涨跌幅指标"
> ```
>
> 用户说："宁德时代所在的板块的涨跌幅"
> 理解补全为："我想查股票宁德时代所在的行业板块今天(最近一个交易日)的板块涨跌幅指标"

这个补全过程只在脑中/推导中完成，不需要输出。

---

### 第二步：分类与识别

判断 query 包含的取数请求的类型关系：

| 类型 | 特征 | 示例 | 输出 chain |
|------|------|------|------------|
| **单一请求** | 1个主体 + 1个指标 | "宁德时代的涨跌幅" | false |
| **多指标请求** | 1+个主体，多个指标用"和/与"连接 | "最高价和最低价" | false |
| **多主体请求** | 多个主体 + 同指标，条件合并 | "宁德时代和比亚迪的股价" | false |
| **链式请求** | var 有"所属/所在/板块/概念/行业"等中间查寻需求 | "宁德时代所在的板块的涨跌幅" | true |

**识别规则：**
- 如果指标（var）可以直接在金融数据接口中查到 → 普通请求
- 如果指标需要通过另外的间接查询才能确定取数主体 → 链式请求

**什么情况下需要 chain？**
- query 中出现"所在板块"、"所属行业"、"属于XX概念"、"母公司/子公司" —— 这些需要先查关系
- 注意：如果 query 直接指定了板块名称（如"电池板块的涨跌幅"）→ 不需要 chain，直接查
- chain 的本质是：**取数请求中的 obj 不是一个可以直接作为数据接口输入的值，需要先查一次**

**chain 中 resN 的正确用法（重要）：**
- 在 chain 请求中，如果第 N 个 request 的 obj 需要用到前面 request 的结果，obj 必须写成 `["resN"]`
- 示例：需要先查出"三一重工的行业"才能查"该行业的龙头股的资金流向"
  - R1: `{obj:["三一重工"], var:"行业", condition:["今天"]}`  ← 查出行业名
  - R2: `{obj:["res0"], var:"龙头股", condition:["今天"]}`  ← 用 R1 结果查龙头股（注意不是 obj:["龙头股"]）
  - R3: `{obj:["res1"], var:"资金流向", condition:["今天"]}`  ← 用 R2 结果查资金流向
- **绝对不要**在 chain 的依赖步骤中把中间值硬编码为 obj（如 `obj:["龙头股"]`），因为实际的龙头股名取决于前面的查询结果，在解析阶段不可能知道

---

### 第三步：输出结构化结果

输出严格按以下 JSON 格式（**不含 query_id，系统自动生成**）：

```json
{
    "requests": [
        {
            "req_id": "R_001",
            "obj": ["主体1", "主体2"],
            "var": "指标",
            "condition": ["条件1", "条件2"]
        }
    ],
    "chain": false
}
```

**字段说明：**
- `req_id`: 请求内唯一，格式 `R_001`、`R_002` 依次递增
- `obj`: 取数对象列表。**尽量将相同指标+相同条件的主体合并到一个 req 中**
- `var`: 取数指标，**单一值**。只能有一个指标
- `condition`: 范围/限制条件列表。可以是时间、实体限定等
- `chain`: 是否有链式依赖。true/false

---

## 拆分与合并原则

### 拆：什么时候拆成多个 request？

**条件 A — 指标不同（必拆）**
> "宁德时代今天的最高价和最低价"
> → R1: {var: "最高价", condition: ["今天"]}
> → R2: {var: "最低价", condition: ["今天"]}

**条件 B — 指标相同但条件无交织（必拆）**
> "宁德时代在今天收盘和上周收盘的换手率"
> → R1: {var: "换手率", condition: ["今天收盘"]}
> → R2: {var: "换手率", condition: ["一周前收盘"]}
>
> 关键判断：今天收盘和一周前收盘是两个独立的、毫无交集的时间条件。即使 var 相同，也要拆成两个 request，因为需要两次独立取数。

**条件 C — 需要链式解析（chain）**
> "宁德时代所在的板块的涨跌幅"
> → R1: {obj:["宁德时代"], var:"板块", condition:["今天"]}
> → R2: {obj:["res0"], var:"涨跌幅", condition:["今天"]}
> chain: true

### 合：什么时候合并到一个 request？

**条件 D — 多个主体 + 同指标 + 同条件（必须合并）**
> "宁德时代和比亚迪今天的股价"
> → R1: {obj:["宁德时代","比亚迪"], var:"股价", condition:["今天"]}

> **硬性规则**：相同 var + 相同 condition 的多个主体，**必须合并到同一个 request 的 obj 列表中**，不能拆成多个 request。无论多少个主体（5个、10个都一样）都放在一个 obj 中。唯一例外：主体是不同类型（如 A股 + 指数）时才分开。

### 条件（condition）提取规则

1. **obj 只放朴素主体本身**，不带定于、范围描述
2. 所有对主体的范围或定性描述，放在 condition 中
3. 如果没有明确时间条件，condition 默认为 ["今天"]

> 示例：
> "宁德时代所在的版块今天的涨跌幅"
> R1: {obj:["宁德时代"], var:"板块", condition:["今天"]}
> R2: {obj:["res0"], var:"涨跌幅", condition:["今天"]}

## 完整示例

### 示例 1：简单单指标
```
Q: 宁德时代今天的涨跌幅如何？

输出:
{
    "requests": [
        {"req_id": "R_001", "obj": ["宁德时代"], "var": "涨跌幅", "condition": ["今天"]}
    ],
    "chain": false
}
```

### 示例 2：多指标
```
Q: 查询宁德时代今天的最高价和最低价

输出:
{
    "requests": [
        {"req_id": "R_001", "obj": ["宁德时代"], "var": "最高价", "condition": ["今天"]},
        {"req_id": "R_002", "obj": ["宁德时代"], "var": "最低价", "condition": ["今天"]}
    ],
    "chain": false
}
```

### 示例 3：多主体同指标
```
Q: 我想知道比亚迪和宁德时代今天中午收盘的股价

输出:
{
    "requests": [
        {"req_id": "R_001", "obj": ["宁德时代", "比亚迪"], "var": "股价", "condition": ["今天中午收盘"]}
    ],
    "chain": false
}
```

### 示例 4：同指标多条件（无交织）
```
Q: 给我查一下宁德时代在今天收盘和上周收盘的换手率

输出:
{
    "requests": [
        {"req_id": "R_001", "obj": ["宁德时代"], "var": "换手率", "condition": ["今天收盘"]},
        {"req_id": "R_002", "obj": ["宁德时代"], "var": "换手率", "condition": ["一周前收盘"]}
    ],
    "chain": false
}
```

### 示例 5：链式取数（需要先解析主体）
```
Q: 宁德时代所在的版块今天的涨跌幅

输出:
{
    "requests": [
        {"req_id": "R_001", "obj": ["宁德时代"], "var": "板块", "condition": ["今天"]},
        {"req_id": "R_002", "obj": ["res0"], "var": "涨跌幅", "condition": ["今天"]}
    ],
    "chain": true
}
```

### 示例 6：链式取数 + 独立指标混合
```
Q: 宁德时代所在的版块的涨跌幅和成交量

分析：
1. 取"板块"是中间值（chain 前置步骤）
2. 涨跌幅和成交量都依赖板块名的查询结果
3. 先查出板块名，再用板块名查两个指标（这两个可以一起查）

输出:
{
    "requests": [
        {"req_id": "R_001", "obj": ["宁德时代"], "var": "板块", "condition": ["今天"]},
        {"req_id": "R_002", "obj": ["res0"], "var": "涨跌幅", "condition": ["今天"]},
        {"req_id": "R_003", "obj": ["res0"], "var": "成交量", "condition": ["今天"]}
    ],
    "chain": true
}
```

### 示例 7：直接指定板块（不需要 chain）
```
Q: 电池板块今天的涨跌幅

输出:
{
    "requests": [
        {"req_id": "R_001", "obj": ["电池板块"], "var": "涨跌幅", "condition": ["今天"]}
    ],
    "chain": false
}
```

### 示例 8：指数查询
```
Q: 查一下上证指数今天的涨跌幅和成交量

输出:
{
    "requests": [
        {"req_id": "R_001", "obj": ["上证指数"], "var": "涨跌幅", "condition": ["今天"]},
        {"req_id": "R_002", "obj": ["上证指数"], "var": "成交量", "condition": ["今天"]}
    ],
    "chain": false
}
```

### 示例 9：比较式查询
```
Q: 茅台和五粮液今天的股价谁高？

分析：问"谁高"，本质是查两者的股价对比。需要查两个主体的同指标。

输出:
{
    "requests": [
        {"req_id": "R_001", "obj": ["茅台", "五粮液"], "var": "股价", "condition": ["今天"]}
    ],
    "chain": false
}
```
